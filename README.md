# Surrogate-Based Online Conformance Checking

Code and data for the paper *Surrogate-Based Online Conformance Checking:
A\*-Supervised Alignment Approximation for Online Identification of
Control-Flow Deviation Types*.

Alignment-based conformance checking gives precise, localised diagnostics, but
computing an optimal alignment is a combinatorial search that is repeated for
every trace and every incoming event. This repository contains the experiment
that replaces that search at runtime: an A\* alignment oracle labels a bounded
set of traces once, offline, and a small recurrent network learns to reproduce
its output, scoring each event in a single forward step. Beyond a conformance
score, the surrogate predicts the **type** of control-flow deviation, namely
*skip*, *insert* or *rework*.

Everything in the paper comes from one notebook, run end to end on the Process
Discovery Contest 2021 corpus.

## Contents

| Path | What it is |
|---|---|
| `poisson_conformance_bench.ipynb` | the full experiment: oracle, anti-log injection, architecture search, training, metrics, streaming inference, timing |
| `data_exact_models/pdc2021/` | the PDC 2021 corpus, as three archives |
| `requirements.txt` | the library versions the published run used |
| `prepare_data.py` | unpacks the three archives into the layout the notebook expects |

The notebook is saved with the outputs of the run reported in the paper, so the
figures and tables can be read without executing anything.

## Setup

Python 3.11 is what the published run used.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux, macOS
pip install -r requirements.txt
python prepare_data.py
jupyter notebook poisson_conformance_bench.ipynb
```

`prepare_data.py` unzips the corpus in place. Run the notebook from the
repository root: it reads `data_exact_models/pdc2021/` as a relative path.

`requirements.txt` pins `torch==2.5.1`. The published run used the CUDA 12.1
build; for that exact build, install it from the PyTorch index first:

```bash
pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
```

The notebook falls back to the CPU when no GPU is visible. It runs there, but
the A\* labelling stage is slow enough that a GPU is worth having.

### Smoke run

```bash
SMOKE=1 jupyter nbconvert --execute --to notebook poisson_conformance_bench.ipynb
```

`SMOKE=1` shrinks every cap: one model instead of four, 150 clean traces
instead of 1000, 3 epochs instead of 30. It checks that the pipeline runs end
to end in a few minutes. **Its numbers are not the paper's** and the notebook
prints a warning saying so.

## The data

The corpus is the **Process Discovery Contest 2021** collection: 96 Petri nets,
480 training logs and 96 ground-truth logs, in PNML and IEEE XES.

> Verbeek, H. M. W. (2021). *Process Discovery Contest 2021*.
> 4TU.ResearchData. https://doi.org/10.4121/16803232

It is released under **CC0 1.0** (public domain dedication), which is why it can
be mirrored here. `data_exact_models/pdc2021/readme.txt` is the original
description shipped with the dataset, including what each six-digit
configuration code means.

The experiment uses four of the 96 configurations for training and evaluation
(`000000`, `100000`, `011010`, `121111`, called Model 1 to Model 4 in the
paper), and twelve for the oracle sweep.

The corpus matters for one reason: every log is generated by the net that
judges it. The reference model is exact rather than discovered, so the oracle
can be verified before it is imitated, and any residual disagreement is
attributable to the surrogate.

Running it produces, in the working directory:

- `poisson_metrics.csv`, per-type and binary scores for each encoder

## Headline results

Four exact models, identical Poisson head, loss and training budget across
encoders. Deviation detection is scored per type; the binary decision is scored
against A\*.

| Encoder | skip | insert | rework | F1 vs A\* | dominant type | speed-up |
|---|---|---|---|---|---|---|
| GRU, 2 layers, h=128 | 0.935 | 0.868 | 0.835 | **0.961** | 0.894 | 4.4x |
| LSTM, 2 layers, h=128 | **0.946** | **0.876** | **0.857** | 0.959 | **0.912** | 4.6x |
| MLP, 512-256-128 | 0.898 | 0.600 | 0.460 | 0.929 | 0.650 | 17.5x |

The LSTM is the deployed encoder. The MLP is the control: it is a
bag-of-activities encoder, blind to order, and it is the cheapest of the three.
Its collapse on *insert* and *rework* is the paper's clearest structural
result. Those two operators add one occurrence of an activity already present,
so they produce the **same multiset** and differ only in position. No amount of
capacity recovers a distinction the representation has discarded.

On the real BPI Challenge logs the surrogate is 23x to 679x faster than online
prefix-alignment, the gain being largest where exact alignment is least usable.

## Reproducibility

Seed 42, fixed across `random`, `numpy` and `torch`. Decision thresholds are
calibrated on the training split only. A\* is timed trace by trace on a
pre-built log after warm-up, which excludes log-construction overhead and is
therefore the measurement most favourable to the oracle; surrogate timings are
medians over five passes after warm-up.

The published run: Python 3.11.9, CUDA 12.1, NVIDIA GeForce RTX 3070 Ti Laptop.
Section 13 of the notebook writes the full manifest.
